# msrChat 压测方案

## 目标
为 Qt 客户端 + Linux 应用层岗位展示并发、性能、内存管理能力。

## 现有基础设施
- `scripts/asan_benchmark.py` — 5 个场景（心跳/并发/重连/聊天/快速断连）+ ASAN 检测
- `server/ChatServer/tests/stress_image_upload.cpp` — 100 并发图片上传

## 新增压测内容

### 1. 并发连接压测（scripts/stress_connections.py）
**展示**: Linux 高并发 TCP 连接管理、epoll/线程池性能
- 场景 A: 500 并发连接同时登录，测量连接建立耗时
- 场景 B: 1000 并发连接同时登录，测量服务端内存和 CPU 占用
- 场景 C: 连接数从 0 线性增长到 1000，测量每秒连接数（conn/s）
- 输出: 连接耗时 P50/P99、服务端 RSS 内存、CPU 使用率

### 2. 消息吞吐压测（scripts/stress_throughput.py）
**展示**: 消息处理性能、RateLimiter 限流、线程池效率
- 场景 A: 单连接每秒 100 条消息，持续 10 秒，测量 ACK 延迟
- 场景 B: 100 连接各发 50 条消息（共 5000 条），测量总吞吐量
- 场景 C: 触发 RateLimiter 限流（超频发送），验证限流正确性
- 输出: 消息吞吐量（msg/s）、ACK 延迟 P50/P99、消息丢失率

### 3. 长连接稳定性压测（scripts/stress_stability.py）
**展示**: 心跳机制、指数退避重连、连接保活
- 场景 A: 10 个连接保持 60 秒，每 5 秒发心跳，验证不掉线
- 场景 B: 模拟网络抖动（随机断开 30% 连接），验证自动重连
- 场景 C: 服务端重启后，所有客户端自动重连并恢复会话
- 输出: 掉线率、重连成功率、重连耗时

### 4. 整合到 asan_benchmark.py
将新场景整合到现有脚本，统一入口运行。

## 执行顺序
1. stress_connections.py — 并发连接
2. stress_throughput.py — 消息吞吐
3. stress_stability.py — 长连接稳定性
4. 更新 asan_benchmark.py 整合入口

## 验证方式
- 在 Linux 环境运行（Windows 下用 WSL）
- 服务端以 Debug+ASAN 模式编译
- 检查 ASAN 报告无内存泄漏
- 输出性能数据到终端
