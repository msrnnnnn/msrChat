# msrChat 全链路代码审查计划

## 目标
逐行分析 msrChat 每条执行链路的代码，检查：
- 合理性：逻辑是否正确，设计是否合理
- 冗余：是否有重复代码、死代码、不必要的复杂度
- 简化：能否用更简洁的方式实现
- Bug：潜在的崩溃、内存泄漏、竞态条件、协议错误
- 规范：命名、风格、头文件组织是否一致

## 项目概览
- **客户端** (Qt/C++): ~40 个文件，涵盖 TCP 通信、聊天、文件传输、图片下载、数据库
- **服务端** (C++/Boost.Asio): ~50 个文件，涵盖会话管理、消息路由、鉴权、文件/图片服务、线程池
- **协议**: Protobuf Message.proto
- **测试**: 客户端 3 个、服务端 6 个测试文件
- **GitNexus 索引**: 2707 符号，5646 关系，62 条执行链路

## 每个阶段的输出格式

对每条链路输出：
1. **链路概述**: 该链路做了什么，涉及哪些文件
2. **逐文件分析**: 每个文件的关键代码段审查
   - 合理性 ✓/✗ + 说明
   - 冗余 ✓/✗ + 位置
   - 简化建议
   - Bug 风险
   - 规范问题
3. **链路级问题**: 跨文件的设计问题
4. **修复建议**: 按优先级排列

## 执行方式

使用 3 个并行 explore agent 同时分析不同阶段，提高效率：
- Agent 1: 阶段 1-2 (协议 + 网络)
- Agent 2: 阶段 3-4 (鉴权 + 消息)
- Agent 3: 阶段 5-7 (文件 + 图片 + 基础设施)

然后汇总所有发现，生成最终审查报告。
